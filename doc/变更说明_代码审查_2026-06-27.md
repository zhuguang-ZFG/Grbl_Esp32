## 1. 逻辑缺陷修复

### 1.1 `Settings.cpp` — `notCycleOrHold()` 条件错误

**问题：** 使用 `&&` 导致条件恒为 `false`，Cycle/Hold 状态下本应被拦截的 Web/`[ESP...]` 命令可能仍可执行。

**修改：**

```cpp
// 修复前
return sys.state == State::Cycle && sys.state == State::Hold;

// 修复后
return sys.state == State::Cycle || sys.state == State::Hold;
```

**影响：** 绑定 `notCycleOrHold` 检查器的命令在运行或暂停期间将正确返回 `Error::IdleError`。

---

### 1.2 `MotionControl.cpp` — 探针 `"Found"` 误报

**问题：** 在探针运动开始前即打印 `"Found"`，误导操作者。

**修改：**

- 删除 `limitsCheckSoft(target)` 之前的 `"Found"` 日志
- 在 `sys.probe_succeeded = true` 成功分支内打印 `"Found"`

## 2. 性能优化

### 2.1 `TelnetServer.cpp` — Telnet 输入日志

**问题：** `push(uint8_t data)` 对每个字符调用 `log_i`，高流量 Telnet 输入会拖慢主循环。

**修改：** 移除 `push()` 中的逐字符及 buffer size 的 `log_i` 调用。

---

## 3. WebUI 与 SPIFFS 任务执行

### 3.1 `WebSettings.cpp` — `runLocalFile`（ESP700）

**问题：** `runLocalFile` 使用硬编码 `char line[256]` 与 `getBytes(line, 255)`，与 Grbl 协议层 `LINE_BUFFER_SIZE` 定义不一致。

**修改：**

```cpp
char line[LINE_BUFFER_SIZE];
currentline.getBytes(line, LINE_BUFFER_SIZE - 1);
```

**说明：** `LINE_BUFFER_SIZE` 在 `Protocol.h` 中默认为 256，行为与 Grbl 主协议一致，并保留 NUL 终止空间。

## 4. 定制纸路模块（`Custom/paper_system.cpp`）

### 4.1 非阻塞等待与运动互锁

**问题：** 原实现使用 `delay()` 阻塞主循环；审查期间缺少与 Grbl 状态机的显式互锁。

**修改：**

- 新增 `paper_motion_allowed()`：在 `Alarm` / `Cycle` / `Hold` / `Homing` 或 `sys.abort` 时禁止纸路动作
- 新增 `paper_blocking_wait()`：以 `delay_msec()` 替代 `delay()`，可在等待期间响应 abort

> **⚠️ 2026-07-06 更正（重要）：** 上述 `paper_motion_allowed()` / `paper_blocking_wait()`
> 仅存在于 `Grbl_Esp32/Custom/paper_system.cpp`，且均为 **`static` 且从未被任何代码调用的死代码**。
> 实际的一键换纸流程在 `Grbl_Esp32/src/PaperSystem.cpp` 的 `paper_auto_change()` 中，它当时
> **并未接入这个互锁**——因此本节声称的“Hold 时禁止纸路动作”**从未真正生效**。真正的 Hold /
> Safety Door 互锁在 2026-07-06 于 src 层重新实现（见下方第 9 节）。本节保留作为历史记录。

**注意：** 真机仍需验证进纸/退纸与 XYZ 联动及 Hold/Alarm 行为。

## 9. 后续修复（2026-07-06 补充）

在 2026-07-06 的复审中，对定制纸路模块补了两处真正生效的运动安全修复（均在 `Grbl_Esp32/src/PaperSystem.cpp`，即实际执行换纸的编译单元；第 4.1 节的 `Custom/paper_system.cpp` 互锁为死代码，不在此列）。

### 9.1 换纸前排空运动缓冲（commit `b8e616f`）

**问题：** `paper_auto_change()`（M721 / `[ESP910]` / 蓝牙重连三入口）与 M711/712/713/716 点动，在开始用软件脉冲驱动纸路电机前**没有排空 XYZ 运动队列**。若 planner/segment buffer 里还有未跑完的 XYZ 运动，纸路脉冲会与主步进 ISR 并发出料。

**修改：** 在 `paper_auto_change()` 入口及三处点动的 `paper_enable_drivers()` 前各加一次 `protocol_buffer_synchronize()`。M30 / 回原点路径调用前已各自 sync，二次调用时 buffer 已空、立即返回，无副作用。

### 9.2 换纸期间 feed hold / safety door 映射为纸路急停（commit `56dfdd9`）

**问题：** 换纸阻塞期间，用户按 feed hold（或触发 safety door）会让 `sys.state` 变为 `Hold`、停掉主 XYZ 步进，但纸路电机的软件脉冲循环**继续运行**——状态行显示 `<Hold>` 却纸路仍在转，构成误导性停止指示与夹手风险（尤其拾落夹紧阶段）。这正是第 4.1 节承诺却从未生效的互锁缺口。

**修改（入口拦截方案，而非事后检测）：**

- `Serial.cpp` 的 `Cmd::FeedHold`、`System.cpp` 的物理 `feedHold` / `safetyDoor` 入口：在 `paper_auto_change_is_running()` 时调 `paper_request_user_stop()` 并**不**置 `EXEC_FEED_HOLD` / `EXEC_SAFETY_DOOR`——避免 `sys.state` 在纸路仍动时误变 Hold。
- `paper_blocking_abort_requested()` 扩展为 `sys.abort || paper_user_stop_pending()`；命中后在下一个 yield 点（每 25 步）走已有的 `paper_auto_change_abort_cleanup()`，停纸路、失能驱动、回 `Idle`。
- 换纸成功结束 / abort cleanup 均清 `paper_user_stop_requested`；`GRBL_PAPER_SYSTEM` 关闭时提供 `#else` 空实现保证链接。

> **⚠️ 本 commit 的两个缺口已由 §9.3 / §9.4 修复，勿单独回滚 `56dfdd9`：**
> （1）急停标志只在 abort/成功路径清除，两个 timeout 失败路径不清 → 见 §9.3；
> （2）急停实际只在 Step2/6/7 传感器搜索循环生效，Step1 弹纸等长脉冲段的 yield 点及 11 处步间检查不感知 user_stop，且 `Serial.cpp` 的 `Cmd::SafetyDoor` 漏拦截 → 见 §9.4。

**与软复位（0x18）策略的分工：** 换纸初期 60s 忽略 `reset` 是**误操作抑制**（防蓝牙连接触发的软复位打断弹纸）；而 feed hold / safety door 是**有意停止**，始终有效并映射为纸路 abort。换纸被打断需重新对位，是可接受的安全代价。

> **验证：** `custom_3axis_hr4988.h` / release 环境 fresh build SUCCESS。

**变更文件：** `Grbl_Esp32/src/PaperSystem.cpp`、`Grbl_Esp32/src/Serial.cpp`、`Grbl_Esp32/src/System.cpp`、`Grbl_Esp32/src/Grbl.h`。

### 9.3 修复 §9.2 引入的急停标志残留回归（commit `414d4e5`）

**问题（自审发现）：** `paper_user_stop_requested` 原本只在 `abort_cleanup` 与成功结束两处清除，但换纸的两个超时失败退出路径（feeder timeout、fast-feed timeout）直接置 `paper_auto_change_running=false` 后 `return`，**不走 `abort_cleanup`、不清标志**。竞态：换纸中按 feed hold 置位标志后，若换纸恰好走 timeout 失败退出（赶在 yield 点检测到标志之前），标志残留 → 下一轮换纸一启动即被凭空误中止一次。

**修改：** 在 `paper_auto_change()` 入口、`paper_auto_change_running = true` 同步处清一次 `paper_user_stop_requested`，保证每轮换纸开始时标志干净，与所有退出路径解耦。

> **验证：** `custom_3axis_hr4988.h` / release fresh build SUCCESS。**变更文件：** `Grbl_Esp32/src/PaperSystem.cpp`。

### 9.4 修复 §9.2 急停覆盖面不全 + Serial safety door 遗漏（commit `6719215`）

**问题（Cursor 复核发现）：**
1. **急停覆盖面不全：** §9.2 声称"每个 yield 点检测"，但实际只有 Step2/6/7 的传感器搜索循环调 `paper_blocking_abort_requested()`（含 user_stop）；其余 10 处纸路脉冲 helper 的 yield 点只调 `paper_refill_segment_buffer_during_blocking()`（当时只返回 `sys.abort`）。而 feed hold 被拦截后 `sys.abort` 不会为真，因此 Step1 弹纸（最多 8000 步）、Step3–5、Step8 等长脉冲段按 feed hold 后，急停要拖到下一个 Step2/6/7 循环才生效——夹手窗口仍在。此外 11 处步间 `if (sys.abort)` 检查也不感知 user_stop，helper 即使提前 return，主流程仍会空跑剩余步骤并最终误报"成功"。
2. **Serial safety door 遗漏：** `Serial.cpp` 的 `Cmd::FeedHold` 有换纸拦截，但 `Cmd::SafetyDoor`（`0x84`，蓝牙/串口下发）没有，与 `System.cpp` 物理引脚路径不一致。

**修改：**
- `paper_refill_segment_buffer_during_blocking()` 返回值改为 `sys.abort || paper_user_stop_requested`——一处改动令全部 8 个 `if(refill())return` 形式的脉冲 yield 点统一感知急停，纸路在 ≤25 步内提前退出。
- 新增 `paper_should_abort_change()`（= `sys.abort || paper_user_stop_requested`），替换 11 处步间 `if (sys.abort)`，使 helper 因 user_stop 提前 return 后主流程立即走 `abort_cleanup`，不再空跑、不再误报成功。
- `Serial.cpp` 的 `Cmd::SafetyDoor` 补与 FeedHold 对称的换纸拦截。
- `abort_cleanup` 先捕获中止来源（`by_user_stop = paper_user_stop_requested && !sys.abort`）再清标志，日志区分 `user feed-hold/safety-door` 与 `host reset`，避免排障误导。

**未采纳的 Cursor 建议：** safety door 中止后仍回 `Idle` 而非进入 `State::SafetyDoor` 锁存——本机 `custom_3axis_hr4988.h` 未定义 `CONTROL_SAFETY_DOOR_PIN`，换纸核心诉求是"停纸路 + 回可用状态"，锁存反增用户困惑，属设计权衡。另 Cursor 误判 `InputBuffer.cpp` 删除 `current++` 是 bug——该 `current` 是每次由 `_RXbufferpos + _RXbufferSize` 重算的局部变量，自增后不再被使用，确为死代码。
