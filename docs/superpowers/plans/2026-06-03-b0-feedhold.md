# B=0 主动 Feedhold 防发抖 Implementation Plan

**Goal:** 当 planner buffer 耗尽（B=0）时主动触发 feedhold 平滑减速，等待蓝牙数据到达后自动恢复，消除 stop-start 微振动（写字发抖）。

**Architecture:** 修改 `check_buffer_watermark()` 函数，在检测到 B=0 且处于 Cycle 状态时设置 `sys_rt_exec_state.bit.feedHold`，利用 Grbl 现有的 feedhold → 自动恢复机制实现"预判式暂停"。不需要新增状态机或数据结构。

**Tech Stack:** C++ (Grbl_ESP32 firmware), PlatformIO build system

### Task 1: 修改 check_buffer_watermark — 添加 B=0 feedhold

**Files:**
- Modify: `d:\Grbl_Esp32\Grbl_Esp32\src\Protocol.cpp:258-275`

**Design rationale:**

当前逻辑仅打印 `[MSG:LOW_BUFFER B=0]` 警告。修改后：
- B=0 且 Cycle 状态 → 触发 feedhold（让步进电机平滑减速停下）
- B > 0 且有 current_block → 自动 cycleStart 恢复（由已有的 `protocol_auto_cycle_start()` 触发）
- 保留原有 LOW_BUFFER 警告输出用于日志分析

**Grbl feedhold 恢复机制（无需额外代码）：**
1. `sys_rt_exec_state.bit.feedHold = true` → `protocol_exec_rt_system()` 检测到并发起 Hold
2. 步进 ISR 执行 deceleration → cycle_stop → `holdComplete = true`
3. 主循环调用 `protocol_auto_cycle_start()`：如果 planner 有 block → 设置 `cycleStart`
4. `protocol_exec_rt_system()` 检测 cycleStart + holdComplete → 恢复到 Cycle 状态

Replace the existing function (lines 258-275) with:

```cpp
// 【Buffer 水位监控 + 主动防卡顿】
// 每 500ms 检查一次 planner buffer 水位
// B=0 时主动 feedhold 防止 segment buffer underflow 导致的写字发抖
static uint32_t last_buffer_check_ms = 0;
static bool     b0_feedhold_active   = false;  // 跟踪我们主动触发的 feedhold
const uint32_t   BUFFER_CHECK_INTERVAL_MS = 500;
const uint8_t    BUFFER_LOW_THRESHOLD     = 3;    // 低水位阈值
const uint8_t    BUFFER_RECOVER_THRESHOLD = 5;    // 恢复阈值（需高于低水位，避免乒乓）

void check_buffer_watermark() {
    uint32_t now = millis();
    if (now - last_buffer_check_ms < BUFFER_CHECK_INTERVAL_MS) {
        return;
    }
    last_buffer_check_ms = now;

    uint8_t planner_free = plan_get_block_buffer_available();

    // 只在 Cycle 状态下干预（Idle/Hold/Alarm 等状态不干预）
    if (sys.state != State::Cycle) {
        b0_feedhold_active = false;
        return;
    }

    // 主动 feedhold：planner 完全空了，上位机数据还没到
    // 不等 segment buffer 被耗尽才被动恢复，提前平滑减速
    if (planner_free == 0 && !b0_feedhold_active) {
        b0_feedhold_active = true;
        sys_rt_exec_state.bit.feedHold = true;  // 触发 Grbl 标准 feedhold 流程
        grbl_sendf(CLIENT_SERIAL, "[MSG:B0_FEEDHOLD B=%u]\r\n", planner_free);
    }

    // 自动恢复：当 planner 重新有数据后，protocol_auto_cycle_start() 
    // 会在主循环中检测 plan_get_current_block() != NULL 并设置 cycleStart
    // 从而自动从 Hold 恢复到 Cycle
    if (planner_free >= BUFFER_RECOVER_THRESHOLD && b0_feedhold_active) {
        b0_feedhold_active = false;
        grbl_sendf(CLIENT_SERIAL, "[MSG:B0_RECOVER B=%u]\r\n", planner_free);
    }

    // 保留原有低水位警告（非零但低于阈值的情况仍有参考价值）
    if (planner_free > 0 && planner_free < BUFFER_LOW_THRESHOLD && !b0_feedhold_active) {
        grbl_sendf(CLIENT_SERIAL, "[MSG:LOW_BUFFER B=%u]\r\n", planner_free);
    }
}
```

## 行为预期

| 场景 | 旧行为 | 新行为 |
|------|--------|--------|
| B=0, Cycle状态 | 打印 `[MSG:LOW_BUFFER B=0]`，可能发生 segment underflow → 发抖 | 打印 `[MSG:B0_FEEDHOLD B=0]`，步进平滑减速停止，等待数据 |
| 数据到达, B≥5 | 自动恢复（如有 underflow 则急停后重启） | 打印 `[MSG:B0_RECOVER B=5]`，平滑加速恢复 |
| B=1-2, Cycle状态 | 打印 `[MSG:LOW_BUFFER B=1]` | 保留警告（未触发 feedhold，留给 segment buffer 缓冲） |
| 换页/Idle状态 | 正常 | 正常（state != Cycle 跳过） |

## 风险分析

- **风险1：feedhold 期间上位机断连** → 系统停留在 Hold 状态，用户可手动 reset。和普通 ! feedhold 行为一致。
- **风险2：B0_FEEDHOLD 后立刻恢复（乒乓）** → `BUFFER_RECOVER_THRESHOLD=5` 提供了滞回，避免频繁切换。
- **风险3：影响正常打印速度** → feedhold 只在 B=0 时触发（planner 完全耗尽），正常打印时 B > 0 不会触发。且 `check_buffer_watermark()` 500ms 检查间隔加上 feedhold 的 deceleration 时间约 100-200ms，总延迟 < 1s，对整体速度影响小。
